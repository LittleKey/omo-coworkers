## 0. 目标与成功判据(引自 I.10 M1)

- 建: 候选登记、来源查看、人工合并、周度与按需即时复核、批准→补丁-人贴、只读检查。
- 测: 真实误报、重复负担、漏记体验、每周处理时间(整理+审批+贴补丁+检查)、手动入口整理增量。
- 成功: 相对用户直接整理纠正实际省事, 待审不持续积压; **判定须有 P5 人审数据支撑, 缺失即"收益证据不足", 不得进 M2**。
- 停止: 审核经常超预算 / 候选大多无用 / 用户更愿意手动记录 → 关闭自动新增, 保留手动入口与已批准内容。
- 硬约束: 插件对目标文件零写入; 无任何注入通道改动; 不改官方 prompt/skills/omo dist; fail-closed。

## 1. 架构总览

```
用户对话: "记住这次纠正"
  → 主模型调 report_correction 工具 (supervisor 插件注册, v2 API)
  → 宿主校验: 根会话? evidence ∈ 同项目真实用户消息(见 D4)? issueId 存在且同项目? → 否则拒绝
  → 写统一根 store (issues.json / events.jsonl, 幂等)
用户终端: supervisor-memory CLI (omo-coworkers bin/, 用户亲手键入=可信审批面)
  digest          → 待审列表+来源摘录+只读检查+周报 (离线可用, 不调模型)
  digest --draft  → 对指定候选一次性外部起草(可选, 可全程人工起草)
  approve <id>    → 三段式: 选定并确认目标 → 展示完整审批对象 → 用户确认(见 D6)
  discard / merge / disable / status / doctor
用户手工把精确补丁贴进目标文件 (v1 唯一生效方式)
```

组件: ①supervisor 插件内新模块 `lib/memory/`(工具+校验+store 客户端) ②CLI `bin/supervisor-memory.mjs` ③统一根 store。插件与 CLI 共享同一 store 读写库代码(同一 `lib/memory/store.mjs`)。

## 2. 决策点

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 载体 | supervisor 插件内模块; 配置开关 `memory.enable`(默认 off, 显式开启) | **配置开关只控制 memory 模块加载, 与候选状态分离; memory 关闭/故障不影响现有 supervisor L0/inject 行为**(P0 回归验证)。遵循 follow-upstream |
| D2 | 宿主 API | OpenCode v2 插件 API。**P0 门槛(全部满足才进 P1, 失败即停, 不退回 v1 定义、不改注入链绕过)**: ①最小工具注册+调用回执 ②宿主可靠提供 session/project/parent/agent 身份 ③可读取真实用户消息(本会话上下文或宿主存储) ④注册 memory 模块后原 supervisor inject/L0 行为不变 ⑤memory 开/关两态下 ④ 均成立 | 生产为 v2; 探针 /tmp/opencode/probe-mem/; "能注册工具"≠"具备来源验证能力" |
| D3 | 手动入口 | 工具 `report_correction`, 由模型在用户明确指示时调用; 工具描述冻结文本: **不主动发现; 禁止把工具结果/模型自评/nudge 当证据; 无有效 evidence 宿主拒绝; 可选 issueId 须存在且同项目(否则本次拒绝, 不静默新建)** | II.2; 返回仅 ack+ID |
| D4 | evidence 校验 | **同项目真实用户消息**(按设计 II.1 全语义, 不收窄): 引用 ID ∈ 当前会话上下文用户消息(快路径), 或经宿主只读存储查得=真实用户消息且其会话 project_id==当前 project_id(跨会话路径); **两种都无法验证 → 拒绝(fail-closed, 不因 DB 不可用降级放行)**; 子会话来源拒绝(agent/parentID 判别); 宿主核验并**保存原始来源(会话/项目/摘录), Issue 合并或升级 global 规则不改变 Event 原始来源** | B1; 同会话⊂同项目, 快路径是优化不是语义 |
| D5 | store 实现 | 纯文件; **全库单锁(flock)+跨文件提交顺序+提交标记**: 每次状态变更按固定顺序写 decisions.jsonl → rules.json/issues.json → 提交标记(含变更摘要), **事务清单逐项列明各操作涉及的文件(含 events.jsonl、projects.json 参与的跨文件变更), T4 按清单逐点注入崩溃**; 启动与 CLI 均检测不完整提交(有标记无内容/有内容无标记)→**关闭授权输出(不发布/不清理/不生成补丁), 报告差异待人审**; 损坏/权限错/锁失败/未知 schema → 不换目录另起库、不恢复旧批准、不生成清理补丁。**首次初始化=显式 `init` 命令(创建目录 0700/文件 0600/空骨架+标记); 库缺失≠新安装, 工具与 CLI 均拒绝并提示**; 人工恢复=备份还原说明(README), **v1 不提供 rebuild** | B4; 量级小, 单锁+标记足够, 不建事务框架 |
| D6 | 审批面 | CLI 由用户亲手键入。**三段式 approve**: ①选定并确认目标(含跟踪文件特别确认) ②展示**完整审批对象**: 规则版本+正文+实际范围+agent 限制+复查日期+通道+目标(+跟踪确认) ③用户当场确认; **确认时重新核对该对象哈希, 正文/范围/目标/期间停用任一变更 → 旧确认失效, 禁止静默重试**; decision 记录展示对象哈希。模型调用工具/写 approved 字段/god-mode ≠ 批准; CLI TTY 交互=用户直接操作的人审终端(不声称人类身份认证, 不设防同权限主动伪造——设计已排除) | B2; I.6 C6 |
| D7 | 起草 LLM | **`digest --draft [id]`: 显式子命令, 仅对指定候选起草**; CLI 直连 newapi(glm-5.3)一次调用; 输入=该候选事件+摘录; 输出=draft 正文; 起草**不能**发现新问题/确认事件/合并/扩大 scope/批准/把历史送回任务会话; 普通 `digest` 离线可用, **人工起草可跑完整闭环(LLM 起草纯可选)**; 失败/超时→留人工起草, 不重试轰炸, 不阻塞人审; 记录失败次数 | I.5 允许起草; I.12 禁的是旁路角色弥补发现失败; 发送内容/凭据见风险表 |
| D8 | 补丁目标 | approve ①中选定: **目标必须=已存在+用户逐目标确认过+加载范围已验证** 三条件齐备; user-global→`~/.config/opencode/AGENTS.md`; project→项目根 AGENTS.md(未被 git 跟踪优先; 被跟踪→decision 显式确认才可用); **不能兑现目录/session/agent 范围 → 保持未发布+说明; 子目录规则不得退到根文件; 无合规目标不得退到 global; 加载顺序未验证(P0 A2)前不推荐任何含糊目标**; 跟踪文件被外部改变(pull/merge/checkout)=目标已变更送人审, 不推断为用户删除 | B3; I.8 |
| D9 | 只读检查 | digest 时对**每条已发布记录(含 active、disabled、已停用旧版本)**: 空白规范化后在已知目标查正文在场/离场; **检查范围含 disabled 正文与旧版本残留**; 漂移只报告不改写; **分开记录三种状态: 已批准 / 待人工应用 / 只读观察到在场或离场**; `disable` 立即: 阻止后续启用补丁生成+输出已知目标移除补丁+标记"库中停用≠文件残留已撤回"; 修改已发布规则: 旧正文留任至新版批准并应用 | B3; I.8; 升级自动发布的触发数据也来自这里 |
| D10 | 效果测量 | digest 人审含: **Event 状态(待确认/确认/误报)、Issue 轻量标注(preference/capability, global/project, 关联模型)、来源摘录查看**; 周报一行: 候选/批准/丢弃/复发追加+处理时间(整理+审批+贴补丁+检查)+重复负担与漏记体验自报+**手动入口整理增量自报(不借助系统是否会想起该候选)**; **缺失值=未知; 计数不得单独宣告"省事"**; P5 缺这些证据 → 判"收益证据不足" | B5; I.10; 不建计时/实验设施 |
| D11 | digest 节奏 | 手动运行(v1 不做定时/推送/催问) | I.6; 即时与周度复核共用入口 |

## 4. 验收清单(映射 v5.0 条款; T*=测试组)

- [ ] **T1 宿主回归**: memory 开/关、真实工具调用与来源读取; 原 supervisor inject/L0 行为不变; 配置或模块失败不使 L0 失效
- [ ] **T2 来源与幂等**: 同项目跨会话通过; 跨项目/非用户/子会话/无效 issueId 拒绝; 同来源串行+并发重复仅一条 Event; mock 不碰生产库
- [ ] **T3 授权与停用竞争**: 草稿/目标/范围变更使旧确认失效; digest 后先停用再 approve→拒绝; 重复 report/merge/草稿重生成均不能恢复授权
- [ ] **T4 故障关闭**: 库缺失/损坏/截断/权限/锁失败/未知 schema/各跨文件写入点崩溃注入; 故障时无启用或移除补丁; 旧备份不自动重发; 库缺失≠自动新建
- [ ] **T5 目标边界**: 未确认路径/共享 project_id 新目录/子目录范围/仅 CLAUDE.md 项目/跟踪目标/未知加载范围/超 10 行/外部目标变更, 各分支正确(不发布/需确认/送人审)
- [ ] **T6 零写入与通道隔离**: 所有 CLI/插件正常+异常路径均不改目标文件; 除统一 store 外无运行时落盘; 无新 nudge; 无历史回送
- [ ] 工具返回仅 ack+ID(II.2); evidence 同项目全语义(D4); 幂等(II.1)
- [ ] decision 含完整审批对象哈希; 展示-确认绑定; 变更失效; 撤销后不得复活(II.1/I.6)
- [ ] 三类精确补丁; 无合规目标→不发布+说明; 超限整体失败(I.8)
- [ ] 只读检查覆盖 active+disabled+旧版本; 三态分开记录; 漂移只报告(I.8)
- [ ] 停用优先: 移除补丁+阻止启用补丁+残留声明(II.3)
- [ ] digest 人审字段与周报齐全; 缺失=未知(D10)

## 5. 风险与未决

| 风险 | 处置 |
|---|---|
| v2 工具注册/身份/消息读取面与预期不符 | P0 五门槛先行; 失败中止计划, 不绕过 |
