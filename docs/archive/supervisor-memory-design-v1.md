## 总览:顶层设计思想与全局图

**一句话**:把「用户纠正」这一最高信噪比事件,经机器**检测与起草**、人工**批准**,转化为窄范围条件记忆,在正确的情境以最小预算注入模型请求,并用受控实验证明它值得存在(核心价值详见 §1)。

**系统 = 三条回路**:学习回路(慢,后台,LLM 只允许在此)、作用回路(快,前台,全确定性零 LLM)、验证回路(离线,决定扩大或停止)。

**顶层思想**(§1 各原则是其操作化细则):
1. **只学用户纠正,不学模型自证**——纠正是对"当前产出不合格"的最强外部信号;模型自己的输出/反思不构成记忆依据。
2. **机器管 recall,人管 judgment**——自动化的只有发现与起草;判断(批准/晋升/撤销)永远属于人。证据分裂(人治有效/自动生成有害)决定了这是价值与安全的共同边界。
3. **热路径零智能**——请求构造路径上不出现 LLM、无界扫描或写操作;一切"聪明"都发生在后台与离线。
4. **单出口、小预算、不常驻**——与 nudge 共用唯一注入出口;每会话至多 1 条、400 token;条件命中才注入,永不全量常驻(Cline memory bank 的失败路径)。
5. **一切可撤销、默认失效安全**——条目有显式生命周期与 TTL;负信号(证据失效/可信反证/过宽)机器即时退出注入;身份或谓词输入未知时 fail-closed 不注入;store 故障熔断且不影响 nudge。
6. **证据驱动演进**——影子→上限先导试验→三臂 RCT 逐级准入门;kill criteria 预先登记;扩大(user scope/提频)须净收益证据,而非"未发现回归"。

## 1. 设计思想(原则,继承 nudge 设计 §1 并增补)

**核心价值(R13 双评审定案)**:用户不应在同一处纠正两次。supervisor-memory 跨会话捕获人漏掉的重复纠错,起草窄范围条件规则,请人批准——自动化官方推荐人工 AGENTS.md 维护闭环中的**检测与起草**两步,**判断步骤永远留在人**。价值以"相对良好人工基线(手工 AGENTS.md+按需 /reflect)减少的纠错成本"衡量,不以记忆数量或通用能力衡量;冷启动压缩仅为副产品,不为它优化(全量常驻注入=Cline memory bank 的失败路径)。**证据依据(分裂一致)**:人治记忆有效(ETH 手写 +4%、MemGovern +4.65% 跨 9 LLM、Lulla wall-clock −28.6%)、自动生成有害(ETH 生成文件 −0.5~−3% 且成本 +20%、Cursor 移除自动 Memories、OpenAI 加记忆衰减)。**相对人工的边际价值仅三项:recall**(自动发现人未整理的重复纠错)、**gating**(承载不宜常驻文件的条件性经验)、**decay**(过期条目及时退出)。

1. **memory-only**:唯一可写对象是本模块自有 store 与 digest;一切"沉淀为 skill/AGENTS.md/prompt 修改"都是人审后的人的动作,插件只产出建议文本。**无条件经验不入注入管线**(claude 重构洞见:注入只对"部分上下文适用"的条件性经验增值;无条件经验经 digest 作 AGENTS.md 建议行,由人应用)。**无条件 profile 条目同样不绕过此禁令**(oracle R9)。
2. **职责分离(不变)**:memory 是可撤销建议,永不 dispatch、永不代表用户批准;终审在 orchestrator/用户。
3. **确定性优先(修订)**:检索、谓词、频控、失效、预算全部确定性代码;**LLM 只进后台分析轨道**(沉淀/蒸馏),永不进入请求构造热路径。
4. **单出口注入**:与 nudge 共用唯一 context hook 注入出口与预算框架;不新增投递通道;**每次模型请求至多注入一条合成消息**([supervisor-nudge] 与 [supervisor-memory] 二选一,nudge 优先;memory 错过的机会等待该会话后续自然请求)。
5. **人审激活**:自动产出只能是 draft;active 必须经 digest 人审;批准绑定内容与范围的 hash;晋升/退役/撤销可追溯。
6. **负信号即时生效**:证据失效、可信反证、过宽命中**先由机器暂停/退出注入**(suspended/digestOnly),撤销等人审;被注入≠仍正确。
7. **失效安全(不变)**:条目有显式生命周期;无法确认有效性时默认不注入。
8. **最小数据与外发边界**:store 不落原始对话,只落脱敏摘要+证据引用;蒸馏外发仅限脱敏证据窗口,发往配置的蒸馏模型;digest 展示差异而非全文。
9. **防投毒(修订,R10)**:**权威 store 与批准通道均在宿主 external_directory 白名单之外**(agent 工具物理不可写,§3);repo 对 agent 可写=投毒面,同理白名单内不可作权威状态存放地。

**准入硬约束**:无影子期证据 ≠ 进入注入;"重复出现"≠"有效";蒸馏器未标冲突 ≠ 无冲突;**身份或谓词输入未知 ≠ 放宽匹配**(fail-closed)。

## 2. 数据模型(单库)

```
entry {
  id, version                     // 内容/范围变更即 version+1
  scope: "project" | "user"       // project 键=宿主 project_id;user 键="*"
  projectKey?: string             // scope=project 时必填
  tags: string[]                  // profile/model/provider 等适用标签(oracle R6/③)
  predicate {                     // ★适用性谓词(claude R8①):蒸馏器产出、人审批准
    globs: string[]               // 会话涉及文件路径匹配
    tools: string[]               // 本会话已用/在用工具名
    skills: string[]              // 已加载 skill
    keywords: string[]            // 当前用户轮次关键词(字面)
    agentTags: string[]           // 适用 agent(定向;M3 才用于子会话投递)
  }
  unconditional: bool             // ★语法恒真:所有维度皆空;仅 digest 建议,永不可注入
  digestOnly: bool                // ★策略退出(R10 消歧):过宽/待裁决等被机器即时
                                  //   移出注入集合但保留条件谓词;人审可恢复或改写谓词
  text                            // 脱敏后的规则/偏好表述,≤1200 字符
  conflictGroup?: string          // ★显式冲突组(oracle R8③);蒸馏器标注,人审可改
  evidenceRefs[]                  // {sessionId, messageId, contentHash, kind}
                                  // kind: user_correction(最高优先) | fix_loop | test_failure
                                  //       | permission_denial | user_statement(仅 profile)
  status: draft | active | suspended | retired | rejected | revoked | purged(墓碑)
  approvals[]                     // {who, when, action, hashOf(id+version+action+scope
                                  //        +projectKey+tags+predicate+text)}
                                  // ★hash 不含 status/digestOnly:生命周期由受保护 store
                                  //   本身+§6 转换规则保证,不依赖 hash(oracle R10)
  stats: { injected, corroborated, corrections, lastPredicateMatchAt,
           lastInjectedAt, predicateMatchRate }
  createdAt / updatedAt
  idleTtlDays                     // 谓词连续未命中 N 个项目活跃天 → digest 退役提议
}
```

**可注入 ⇔ status=active 且 !unconditional 且 !digestOnly 且资格门通过**(§5);`digestOnly` 与 `unconditional` 是两个正交概念:前者保留谓词、可被人审恢复/收窄后重回注入集合,后者语法上就无谓词、永远只作 digest 建议行。

- **session 记忆不入库**(内存);**profile 不是第三 scope**:`scope=user + tags 含 "profile"`,只收用户明确说出的全局陈述(禁推断),独立审批流程(§6),不受跨项目占比门约束(oracle R6 建议3)。
- **谓词求值契约**(oracle R9 ③,所有调用点统一,不得自行解释):
  - 维度语义:数组**空=该维度不约束**;非空=至少一个元素字面命中;维度间 **AND**(全部非空维度须命中)。
  - `unconditional` ⇔ 所有维度皆空;任一维度非空即条件性。**仅 keywords 非空的谓词在审批时拒绝**(claude:关键词单独过脆,须叠加其他维度)。
  - 求值输入未知(无法确定文件集/工具集/agent)→ 该维度按**未命中**处理(fail-closed)。
  - 求值时机:每次 context hook 对当前请求确定性求值(会话文件集、已用工具、当前轮关键词)。
- **TTL 语义**(claude R8②/oracle R8④):`idleTtlDays` 按**谓词未命中的项目活跃天**计(该 project 当日无任何会话则不计天——防假期退役一切,claude R9);时钟自**批准激活**起算(冷启动);注入次数、正确性与此期限解耦;digest 期对每个 glob 检查仍匹配至少一个文件,**零命中标 `dead`(路径已改)与 `idle`(未再出现)分开列**(claude R9)。

## 3. 存储与身份(R10 修订:全部权威数据在白名单外)

- **权威根目录 `memoryRootDir`**:`~/.local/share/opencode-supervisor-memory/`——宿主 external_directory 白名单(`~/.local/share/opencode` 等前缀)**不覆盖**该路径,agent 的文件/shell 工具写它会被拒。其下:`store.jsonl`(追加+空闲期原子压实 tmp+rename)、`directory-map.json`、`digest/`、`approvals/`。**插件进程以自身权限读写全部文件;人直接读 digest、填 approvals;agent 只可能读到(读不构成篡改面)。**
- **信任链(R10/R11)**:权威状态(status/digestOnly/approvals)存于 agent 物理不可写的 store;§6 hash 复验降为**纵深防御**(防插件自身 bug/未来权限变化),不再是防 agent 篡改的主手段。**验收(oracle R10 三连,M0/M1 均跑):①仅改 status ②伪造 store 内 approvals 记录 ③回放旧 active 快照——在 agent 会话中尝试写 store/approvals 均被权限拒绝,三连攻击不可达。****验收语义澄清(oracle R11,属准入条件而非兜底)**:目录名在白名单外本身不证明不可写——测试须覆盖文件工具之外的 shell 间接写(python/node/脚本)、路径别名、文件替换;若同 UID 任意 shell 且无有效隔离,应用层路径检查不构成安全边界;**这些测试失败即准入不满足,不得以 hash 兜底**。
- **隔离边界决策(claude R12,M0 第一步、写任何 store 代码之前)**:同 UID 任意 shell 大概率击穿路径隔离(一行 `python -c` 写入即绕过白名单;oracle R11 已预告路径检查可能不构成安全边界)。在真实宿主以 agent 身份实跑三连+间接写攻击(python/node/symlink/rename 替换文件,约 1 小时):若路径隔离**实测**成立(宿主存在有效沙箱如 bwrap/Landlock,或权限层实际拦截间接写)→ 维持白名单外路径方案;**若任一攻击成功(claude 预期如此),必须先选定以下真实边界之一再实现 store**:①独立 UID 写入器(dedicated user 运行小型写入门面,如 systemd 服务;agent UID 无权写 store、无权读其凭据)②keyed MAC:对 `(status, version, 单调计数器)` 计算 MAC,密钥置于 agent UID **不可读**位置(独立用户所有),每次状态读取校验,计数器防回放旧快照——**此 MAC 非此前否决的普通 hash 兜底**(被否决者是同 UID 可重算的内容 hash;密钥不可读即构成边界)。两种机制实现草图先行,纳入 M1 前置验收。
- **身份适配器**(oracle R8 建议1):所有宿主 project_id 访问收敛到 `lib/memory/identity.mjs`:PluginInput.project 优先、`session_v2.project_id` 只读核对、directory-map 迁移(宿主升级/DB 重建后重推导)。**身份缺失/冲突/不可信:该会话的候选隔离为草稿并停止该项目检索,绝不降级 user scope**(oracle R8①);用户明确全局陈述走 profile 流程,不依赖此兜底。
- 检索的阶段 scope 门:**M1 只允许 scope=project;M2 起才允许 user**。
- 否决仓库内存储与白名单内权威存储(理由同上);团队共享未来形态=人审脱敏导出,不自动导入。

## 4. 沉淀轨道(后台,硬预算)

- **触发**:`session.idle` + 去抖 10min + 有新证据;每日上限 6(跨重启持久计数);同 evidenceHash 去重;递归防护(蒸馏会话被现有黑名单排除;memory 不触发蒸馏)。
- **蒸馏硬预算表**(oracle R8⑥,启用 M0 蒸馏前填入并验证):

| 项 | 上限 |
|---|---|
| 单次输入(脱敏证据窗口) | ≤24000 字符 |
| 单次输出 | ≤2000 字符,**在生成端参数落实(如 max_tokens),非收后截断**(oracle R9) |
| 超时 | 90s;超时/结果未知**不得立即改跑 judge**(计入占用,防止双计费) |
| 并发 | 1 |
| 队列 | ≤8,溢出丢弃记日志 |
| 每日额度 | 6 次/宿主日,持久计数,重启不清零 |

- **能力探测(分别验证后才可用)**:`ctx.generate.text`(M0 探测可用性/模型指定,**并验证蒸馏确实落在配置的蒸馏模型上**)与一次性 judge 会话(禁工具、不挂 parentID、事件排除、用后清理四项逐一验证)为**两条独立路径**;API 不支持才切换到另一条**已验证**路径;两条均不可用 → 蒸馏停止,降级为仅日志证据积累(沿 nudge §2.3)。
- 证据优先级:用户明确纠正 > 修复循环/测试失败/权限拒绝(仅线索,只读)。脱敏在**外发前**;输出结构契约沿 nudge L1 契约(有限字段、来源引用、确定性校验,无效即弃)。
- **漏斗计数(oracle R14 P1)**:沉淀轨道按层记录处置结果——确定性筛掉 / LLM 判非纠正 / 预算·队列丢弃 / 生成候选,各留**消息引用与原因**(不另存整份对话)。否则"模型没识别"与"根本没处理"无法区分,§7 负例审计也无从分层抽样。

## 5. 检索与注入(单出口,门序)

执行点:context hook 内,确定性代码。**门序**(oracle R9 新1,资格条件统一为一条复合表达式):

1. **资格门(fail-closed)**:阶段允许该 scope **且**(`scope=user` **或** 可信会话 project_id == `entry.projectKey`)**且** 非 unconditional **且** 非 digestOnly **且** 谓词按 §2 求值契约命中。身份或谓词输入未知不得扩大匹配。**验收用例:相同谓词、不同项目不得命中**。
2. **状态门**:status=active 且非 suspended(权威状态来自 §3 受保护 store;hash 复验为纵深防御)。
3. **冲突门**(oracle R8③/R10 澄清):对当前**全部资格通过条目**(含跨 scope:project vs user)检查 conflictGroup,并跨批次对照现存条目库;**unconditional/digestOnly 条目仅作只读冲突参照集**(提示"与某 digest-only/无条件建议冲突"),**不因参与冲突检查获得任何注入资格**。命中冲突 → **双双不注入**,进 digest。
4. **预算门**(oracle R8⑤):**token(400)与字符(1200)双限独立执行**,包装文本计入;无法可靠计量 token 时保守拒绝超限候选。

- **排序**(资格通过的候选间):user_correction 证据 > corroborated 数 > 新近度;无 stats 的新条目按**谓词特异度(非空维度数)→ 批准新近度**排(claude R9 冷启动),不饿死。
- **注入形态**:≤1 条/会话,`[supervisor-memory]` 合成 user 消息+结构化元数据(id、version、scope、谓词摘要、证据计数);同轮幂等;与 nudge 共享出口时**每请求一条、nudge 优先**(§1.4)。
- **失效语义**(oracle R8④):新真实用户输入使**本次投递候选**作废(不 invalidate 持久条目);轮次推进**不重置**会话预算。
- **槽位(oracle R9 新2,从简)**:**取消保留槽**,沿用 nudge 优先;每会话合成消息总数帽 3(nudge+memory 合计)、合计字符帽 2400 **仅在 memoryMode=inject 时生效**(显式声明:这是对 nudge 现状 3×1200 的收紧;shadow/off 期间 nudge 预算不变)。影子期度量 nudge 挤占率(命中 memory 但 3 槽被 nudge 占满的比例)——**挤占率是硬门而非仅上报数字(claude R12)**:按"该会话随后是否发生纠正"分解上报,且 **M2 保留槽重评阈值在影子数据到达前预先登记**(防事后拟合);若达标,M2 再评估保留槽——届时必须仅由**通过完整资格门**的可投递候选触发、定义释放规则、已耗槽不追溯预留。
- **注入对象**:M0–M2 仅根会话;agentTags 定向子会话投递为 M3(通道已验证,保守推迟)。

## 6. 审批、晋升与生命周期(oracle R8②④、R9 ②④、R10)

**批准机制**:插件为每条 digest 提议生成**只读 proposal 模板**(proposalId、entryId、version、action、expectedHash=hashOf(scope+projectKey+tags+predicate+text)),写入 `memoryRootDir/approvals/`;**人只填 verdict**(approve/reject/defer),不改其余字段;应用器原子复验 `id+version+action+expectedHash` 全匹配才执行;不一致 → 批准无效需重审;检索时复验 hash 作纵深防御(权威防篡改=§3 物理不可写)。工具权限放行≠内容批准;实际写入路径仅 `memoryRootDir` 下文件(实现期验证)。

| 转换 | 条件 | 执行者 |
|---|---|---|
| draft → active(project) | ≥1 次用户明确纠正 或 ≥2 独立批次佐证 + digest 人审 | 人(经 approvals) |
| project → user 晋升 | 同一规则在 ≥2 project active 且各有佐证 + 人审;**生成新 user 草稿引用原证据,禁止原地改 scope** | 人 |
| profile 条目 | 仅用户明确全局陈述 + 人审(独立流程,不受跨项目占比门约束);无条件 profile 仅 digest 建议 | 人 |
| active → suspended | **两类分开**(oracle R9 ④):A 条目有效性反证——证据引用失效(message 删除/会话压缩)或**任何会话**出现的同题明确反证(不要求本会话已注入):可靠反证**立即停**;疑似反证保守暂停;B 注入后效果统计——corrections≥1 **且可归因**(该条目本会话已注入且纠正指向其主题,蒸馏器标注"建议错误"vs"建议正确未执行") | **机器即时** |
| suspended → active(恢复路径) | 后台归因否决反证 + 人审恢复(oracle R9 ④) | 人 |
| active → digestOnly(**策略退出注入集合,R10**) | `stats.predicateMatchRate > 60%` 该项目影子会话**且该项目影子会话数 ≥10**(claude R12:防新项目两会话即触发)——**机器即时退出注入集合**(非仅待审提议期间继续注入,oracle R10 消歧);digest 提议人审裁决:确认转 digest 建议行 / 收窄谓词后恢复 / 退役 | **机器即时退出,人审裁决** |
| suspended → revoked | corrections≥2 强制提议;人审执行 | 人 |
| active → retired | 谓词连续 idleTtlDays(默认 30)项目活跃天未命中 → digest 提议;**dead glob(§2)单独列示** | 人 |
| 任何 → purged | 隐私删除请求(任何人可提) | 人提,机器执行 |

- **purge 覆盖范围**(oracle R9 新4,M2 前落地):store.jsonl 中该条目**全部历史版本**(触发一次全量重写压实,非仅追加墓碑)、evidenceRefs、digest 文件中的正文(重写)、压实临时副本;墓碑 `{id, reason(不含敏感原文), 原 contentHash}` 防重提案。**验收:植入合成敏感标记→执行 purge→全目录扫描零残留**(非仅查最新状态)。
- **插件为可信组件(oracle R11)**:隔离与 hash 均不防插件自身错误回写(hash 不检测未绑定 status/digestOnly 变化)。转换/恢复测试须验证:**蒸馏输出不得直接覆盖权威状态**(status/digestOnly 变更仅经本表规定转换发生);**suspended/digestOnly 恢复必须走人审转换**。
- **晋升语义检查(oracle R14 P3)**:digest 审批 draft 增加两问——**今后同情境仍适用吗?适用范围是否忠实于原话?**任一不确定 → 留草稿不激活(防一次性/情绪化纠正被泛化;用户对需求的权威≠一句话自动成为跨项目事实;不加情绪分类器)。
- retired/rejected/revoked/purged 检索排除;墓碑与审计记录永久保留。

## 7. 人工闸门(digest)

- 周期(默认每周)`digest/<week>.md`:新增 draft 及证据摘要、激活/晋升/退役/撤销/恢复/digestOnly 裁决/隔离提议(带差异,**附只读 proposal 模板**)、**无条件条目(含无条件 profile)的 AGENTS.md 建议行**(人复制进 AGENTS.md,插件不写)、注入统计、预算消耗、**每谓词命中率与 dead/idle glob 清单**(over-breadth 数据源)、nudge 挤占率。
- **负例小额审计(oracle R14 P1;与 §8 标签抽查共用 30min/周人工预算帽)**:每周人工检查 ≤12 个原始消息窗口——确定性筛掉 6、LLM 判否 3、未处理 3(层内随机抽取;记录各层总量与抽样概率,空层配额才重分配)。判定区分**"确为纠正"与"值得入库"**两件事。统计克制:按抽样权重估计漏检及区间,不得把富集样本当总体比例;低基率下小额审计只能发现漏检类型、不能认证高召回,**零漏检≠召回达标**。
- **`/reflect <消息引用>` 显式入口**=补救通道:绕过候选筛选、进入草稿,**不绕过批准**;它是补救路径,不是无偏召回样本。
- v1 交互=文件+日志提醒;Android 审批链路后续,不阻塞。

## 8. 验证与准入门(oracle R8⑦、R9、R10、claude R8③/R9)

**M0 准入(回溯标注,已完成 2026-10-21)**:近 8 周用户消息 3353 条 → 52 条逻辑纠正(过程与噪声过滤见报告);复发 38(73%)/非复发 14;条件性 41(79%)/无条件 11;交叉:复发×条件 27、复发×无条件 11、非复发全条件。**结论:full M0**——复发样本 71% 条件性,digest/AGENTS.md 常驻无法覆盖条件触发;无条件子集(11)作 digest+AGENTS.md fallback 层。强佐证:用户常态同文并发 3-8 会话,纠正无法跨会话传播。种子主题:①产出臃肿(≥10 会话)②范围蔓延"不需要X"(≥8)③上游/既有机制不可侵入(≥6)④分支/构建新鲜度(4 会话/47 天)。边界案例(msg_15d2e105:用户曾考虑移除自己 AGENTS.md 规则章节)→ 规则版本化/撤销列为 M0 验证场景。报告:`/tmp/opencode/memory-lookback/report.md`。**基线声明(oracle R9):73% 是筛选后纠正中的主题复现率,≠任务机会纠错率;任务机会层面的基线在 M0 影子期重新测量后方可作 M1 对照。**

**M0 影子期**(蒸馏+digest,注入恒关):日志四元组 `(sessionId, 任务指纹, entryId+version, wouldInject)`;wouldInject 按会话/轮次去重(模拟消费预算);度量:①谓词命中会话中同题纠错复发率(任务机会基线)②每谓词命中率(over-breadth)③跨项目候选占比 ④nudge 挤占率。

**召回边界(oracle R14 P1)**:漏检(false negative)监测仅由 §7 负例审计承担;**禁止用复发率反推检测召回**(复发同时受提醒有效性、任务变化、用户反馈习惯影响)。降级链:审计样本不足以形成有用区间 → 降为**漏检哨兵**(只报告发现的漏检,不公布"召回合格");原始窗口不可得或连续两期超出预登记人工预算 → 取消总体召回评估、保留 /reflect 入口;被动发现的增益也不抵成本 → 停被动蒸馏。P1 漏检首先损害覆盖率,不单独触发停注入,最终由净收益判据(kill #3)处理。

**M1 前回放校准**(claude R9/R12,只读历史、属探索性校准非评估):为 27 条复发×条件性纠正手写谓词,对 8 周历史请求回放,报告:recall(复发前谓词是否命中)、无纠正会话命中率(过宽)、批次机会数/周与基线复发率→**检测 50% 下降所需周数**;若 >12 周,M1 冻结时限制在最忙 2-3 个项目。**逐请求点时求值(claude R12)**:谓词只用该次模型请求时刻已知的输入(当时已触碰的文件、已用工具、当轮关键词),**禁止用全会话文件集回填**——否则 glob 谓词会被系统性高估。

**M1 前上限先导试验(oracle R13,最廉价的方向证伪,先于任何管道建设)**:用 M0 回放样本做"最佳条件"试验——人选条目+人定触发时机(27 条复发×条件性纠正),测"把对的短提醒放到对的情境"能否覆盖下一次同类错误。**若上限试验失败,方向证伪,停建管道**(再好的 memory 管道也救不了方向);回放中 >50% 复发类无法从请求时刻文本预测(claude R13)同判。

**M1 准入**:
- **评估样本采集前冻结** N、指标、停止条件;**N 的独立单元=并行批次**(同文并发批次=1 个机会,非会话数——claude R9①,相关性修正)。
- **对照设计=批内随机化**(claude R9①/oracle R9 收敛):批次 ≥2 时随机选注入/留白,形成**同期并发对照**(优先于历史基线;历史 M0 基线仅探索性);**评估期冻结被评估主题的 AGENTS.md 变更与 digest 激活**(人执行,防消化道干扰对照)。**按指派计分(ITT,claude R12)**:分配即记 `assigned=inject|withhold`,投递成败另记 `delivered`;"nudge 优先、每请求一条"造成的挤占性未投递**不改变分组**——分析一律按 assigned 分组、delivered 单独统计;否则 inject 组恰好丢失 nudge 最频繁(纠错最可能复发)的会话,效应估计系统性有偏。**三臂对照(v1.5,R13)**:①留白=良好人工基线(评估期冻结的 AGENTS.md+按需 /reflect 现状;对照对象是人工基线**而非空白上下文**——oracle R13:手工+/reflect 已覆盖大部分稳定规则价值,与空白比较会夸大净收益)②谓词注入③静态臂(批准条目静态 append 进冻结 AGENTS.md 副本;build-vs-buy 检验——claude R13:静态臂与谓词注入无差异→砍注入引擎,仅留 digest 提议 AGENTS.md diff)。**复发标签器独立于蒸馏器**(claude R13,防同源偏置);不得只统计已注入会话——"用户少纠正≠做对了",须同看任务质量/返工/约束违背(oracle R13)。**标签器盲法(v1.5.2)**:复发标签器的输入必须剥离 `[supervisor-memory]`/`[supervisor-nudge]` 合成消息及一切 assigned/delivered 分组标记——对分组盲,否则标签偏置直接污染对照;复发判定定义与标签器 prompt 纳入 M1 冻结清单;digest 周期性抽查标签一致性样本——**标签失控语义=实验结论失效(≠记忆条目错误,条目处置照常走 §6)**,完整协议见下「标签验收协议」。
- **冻结清单必须包含(R10)**:过宽即时退出注入集合(digestOnly 机器即时)已生效;unconditional(语法)与 digestOnly(策略)消歧已实现。
- **前置验收**(注入开启前,不得后补):与 nudge/blackboard/PHASE_REMINDER 同请求组合测试;**审批与状态完整性(approvals/store agent 写入被拒;仅改状态/伪造批准/回放旧快照三连不可达;shell 间接写/路径别名/文件替换同被拒——R11)**;**插件回写约束(蒸馏输出不直接覆盖权威状态、恢复仅经人审转换——R11)**;**标签挑战集通过(标签验收协议,R14——校准证据就位前 M1 不得开始,效果结论可信度前提)**;失效/冲突/恢复路径;重试幂等;真实 provider 冒烟;§9 隔离契约故障注入(含 circuit-open 后无新增模型调用与写重试)。
- 注入使用**冻结条目版本**;扩大(user scope/提高频次)须有**净收益证据**(复发率下降),非"未发现回归"。

**标签验收协议(oracle R14 P2,v1.6)**:
- **判定单位=任务窗口**,四问:是否真发生纠正 / 是否违反同一冻结约束 / 是否新任务机会(非同一修复过程的重复催促)/ 证据是否完整;输出 是/否/不确定+证据引用,**不确定≠无复发**。人工参考判定先独立完成、后看模型标签,隐藏组别与模型答案(单用户场景仅"尽力盲法",不承诺完全盲)。
- **挑战集(M1 前)**:用未参与调 prompt 的约 60 个窗口(尽量 ≥20 真复发+20 近似反例+需求变更/歧义案例)做能力检验;它检验能力,不估计总体发生率。
- **周抽查(M1 中)**:每周 ≤18 窗口——三臂各抽 3 个预测阳性+3 个预测阴性(不足取全),记录抽样概率,未知标签单列。
- **质量门与误差预算**:按抽样权重还原后 precision/recall 各 90% 仅作**运维报警线**,非效果可信的充分条件;禁止用总体准确率过关。预登记最小有价值收益为绝对差 **Δmin**;要求审计允许的**组间差异性错标偏差上界 B < Δmin/2**(如目标改善 5 个百分点,测量偏差不得容许制造 2.5 个百分点假改善)。最终做**错标敏感性分析**:在审计允许误差内效果可翻转或跨 kill 阈值 → 结论="不确定"(少量抽查约束不了小效应时,"90% 一致"不构成证据)。
- **漂移**:固定约 20 个锚点,标签模型版本变化时重跑;周报监控未知/新主题/人机分歧,连续两期分歧或未知比例超预登记阈值(启动取 10%)触发**复核**而非自动改主题词典;仅修标签器错误=**同版本重标全部组**,改"何为复发"定义=另开阶段,不静默混合统计。
- **降级**:质量报警或 B 无法约束到所需幅度 → **暂停效果判决、转人工结局标注**,不自动扩大注入;人工超预算 → 缩小预定义主题范围或只作探索性报告。**规则+主题聚类可替代 LLM 做初筛,但不得默认承担主指标判定**——粗聚类合并异质约束增假复发、细聚类拆散同义纠正漏复发,净偏置方向不固定;"规则看不到分组"≠无差异误差(注入可能改变用户措辞,两组规则召回可不同);M0 的 73% 不构成其质量证明。**LLM 非必需组件:优先"规则定位证据+人判结局",量大到人工承受不了再保留一个冻结的 LLM 标签器;不加第二/第三模型投票制造虚假可靠性**。

**结局与对照卫生(oracle R14 P3,v1.6)**:
- **护栏结局**:优先可验证产物(测试/构建/产物检查);主观质量由隐藏组别的人工按固定标准判定,LLM 仅提取证据、不独自裁决成功("未被纠正"不能代替成功)。
- **行为效应(Hawthorne/补偿/跨臂传播)**:各臂任务结束检查一致、不展示即时胜负、不要求用户忍住纠正;轻量记录跨会话复制提示/额外指导/提前放弃,**不利病例不得事后剔除**;不建用户行为校正模型。
- **三臂公平**:三臂共用同一批准条目池、基础指令、模型与任务条件;静态臂用冻结 AGENTS.md 副本隔离,不污染他臂;常驻 vs 条件命中的曝光差异是**策略差异**而非混淆,但结论不得声称只测到"谓词算法"。
- **机会集**:任务机会在**分组前**定义;不得以各臂运行后的谓词命中作主分析分母;未投递按 assigned 计,失访/未验收≠成功。
- **历史与效果分离**:同一批历史既产规则又校准谓词,**效果证明只用后续任务或冻结任务重跑**;回放上限试验度量的是**触发覆盖率,不是行为改善**——无显著收益≠自动方向证伪(上限试验的证伪语义见 kill #2)。
- **冻结期例外**:安全反证可即时暂停条目,但**保留原分组与暂停记录**,失败会话不移出实验。
- **降级**:护栏不可靠判定 → 只评估少量可验证任务、不声称整体任务质量提升;跨臂污染致敏感性分析无法支持结论 → 降为探索性观察,**不加统计模型"救显著"**;期限内三臂无法获得有判断力样本 → **采样前改两臂回答一个问题**(如同一经验池"静态 vs 条件加载"),第三臂延期、不事后挑赢家;人工无法稳定区分纠正/需求变化/复发 → 停止自动结论,退回人工经验维护。

**度量**:纠错复发率(注入 vs 同期对照)、跨项目候选占比(<10% 门,约束蒸馏型 user 条目)、上下文膨胀、蒸馏成本。

**Kill criteria(R13 双评审合并;触发即停,阈值可在数据到达前校准登记、不得事后放宽)**:
1. **机会不足**:M0 同类纠错 30 项目活跃天内复发 <15%(claude),或可复用条件性纠错太少、最忙项目也无法在期限内获得有判断力样本(oracle)→ 停扩建,退回按需 /reflect。
2. **上限证伪**:回放中 >50% 复发类无法从请求时刻输入预测,或人选条目+时机的上限先导试验仍无收益 → 方向证伪,停建管道。
3. **净收益不抵**:M1 复发率相对下降 CI 排除 25%(claude)或低于预设最低价值(oracle),或护栏回归(任务成功降/上下文 token 涨 >10%/错误完成与返工增)→ 停注入;节省纠错成本持续低于审批+维护成本 → 停后台闭环,保留有效静态经验。
4. **审批健康**:批准率 >90% 且中位审阅 <10s=橡皮图章(静默滑回自动生成有害区间)→ 收紧 digest 节奏与呈现;批准率 <30%=蒸馏噪声 → 重校蒸馏器。
到期证据不足=停止扩大投入,**不等同证明无效**(oracle)。

## 9. 阶段计划与隔离契约

| 阶段 | 内容 | 准入 |
|---|---|---|
| M0 | **宿主攻击演练(三连+间接写,定隔离边界,claude R12)→ 按结果定 store 边界方案** → 探测 PluginInput.project/ctx.generate.text → 影子蒸馏+digest;零注入 | §8 M0 准入 + 本设计定稿 |
| M1 | project scope 低频注入(**三臂:人工基线留白/谓词注入/静态 AGENTS.md**);§8 前置验收全过 | M0 影子达标 + 上限先导试验 + 回放校准 + 冻结门 |
| M2 | user scope(+profile 独立流程)+跨项目晋升+purge 全历史机制+保留槽再评估 | M1 净收益 + 跨项目占比数据 |
| M3(可选) | agentTags 子会话定向投递;人审脱敏导出 | M2 稳定 |

**隔离契约**(oracle R8⑧/R9 新3,可测试):
- memory 模块任何异常 → 返回空候选;**不中断共享 hook、不污染 nudge 候选、不重置 nudge 预算**。
- 热路径(context hook 内)禁:LLM 调用、无界文件扫描、store 压实(压实只在空闲调度);store 索引惰性加载有界。
- store 单写者(插件进程);损坏/磁盘满/超时 → **circuit-open(独立于 memoryMode 的熔断态)**:停止新蒸馏、停止 store/digest 写入与压实,仅保留有界诊断日志;nudge 不受影响;**恢复需健康检查通过**(磁盘可写、store 可解析)后才回 shadow/inject。**注意:不得降级为 shadow 继续跑**——shadow 仍会蒸馏与写盘,会继续消耗故障资源(oracle R9 新3)。
- 故障注入测试(nudge 正常工作 **且 memory 无新增模型调用与写重试**)= M1 前置验收项。
- 与 nudge 阶段三/四独立推进,不捆绑。
