## 0. 一句话与演进

**它从我的明确纠正中起草一行规则, 我批准后写进项目指令文件的受管段落, 从此常驻生效。**

演进: v1.x(谓词注入 + RCT + 防篡改契约)被用户判定过重 → 新 oracle 最小设计(条件提醒器)→ claude 评审 proceed + 挑战最高杠杆假设 → replay-27 实测触发词命中率 22% < 50% 预登记阈值 → 按预登记分支落此形态。

依据链:
- 文献: 人审小文件是唯一无争议有效形态(Lulla ICSE 2026: 人写 AGENTS.md wall-clock −28.6%/token −16.6%; ETH: LLM 生成文件 −0.5~−3%, 手写 +4%); 厂商撤退(Cursor 移除自动 Memories)
- 官方推荐闭环: Codex "同一错误犯两次 → 更新 AGENTS.md" — 本设计只自动化"发现 + 起草"两步
- 实测: 8 周 52 条明确纠正(≈6.5/周); replay-27 证明纠正多为过程/协作类, 错误前任务消息不会点名其主题词

## 1. 设计思想

1. **只学用户明确纠正**: 发现靠固定句式线索, 判断靠人; 模型自证、工具输出、网页内容不是纠正源。
2. **落点是项目指令文件**: 常驻、可读、可手改、随 repo 走; 不建运行时注入引擎(门控守着不稀缺的 2KB, 召回才是稀缺品 — replay-27 的教训)。
3. **fail-closed**: 任何不确定 → 不写、不改; marker 异常 → 停止自动写并报告。
4. **一切可见**: 写过的每一行、跳过的每一次(含原因)都有日志; 总开关可停。
5. **follow 上游**: 不动官方 prompt/skills; 插件只在自有受管段落内活动, 机器不得改已批准行。

## 2. 数据流(唯一管道: 发现→起草→批准→写入→生效→淘汰)

- **发现**: 仅新增真实用户消息(排除 subagent/派发/合成); 固定纠正句式线索("不是 X 而是 Y"、"以后不要"、"应该用 X"类); idle 去抖; 候选上限 5, 满则暂停起草(防止堆积)。
- **起草**: 后台一次性小模型调用; 输入 = 纠正原话 + 被纠正答复摘录 + 现有受管段落数行(用于去重与改写判断); 输出 = 一行规则 + 纠正原话引用 + 来源链接; 失败即跳过, 不重试风暴。
- **批准**: 待审列表由用户主动打开(无推送 digest); 批准对象 = 这行文字本身, 所见即所写。
- **写入**: AGENTS.md 受管段落(见 §3); 只在段内 append/replace。
- **生效**: 常驻。段落 ≤10 行 × ~80 字符 ≈ <1KB, 上下文成本可忽略。
- **淘汰**: 手动删除(直接编辑文件即可, 插件容忍); 复发联动: 新纠正与已有行同主题 → 该行计数 +1, 待审列表提示"此行第 N 次被纠正, 考虑改写或删除", 不重复起草新行。

## 3. 受管段落规范

```
<!-- supervisor-memory:begin (managed; one rule per line; edit freely) -->
- ...
- ...
<!-- supervisor-memory:end -->
```

- 首次写入: AGENTS.md 不存在则创建; 已存在则段落追加到文件末尾。
- 写入前重读文件; marker 缺失/重复/嵌套异常 → fail-closed, 停止自动写并报告。
- 段落超 10 行 → 拒绝新增, 待审列表要求先淘汰。
- 删除规则 = 直接删行, 无墓碑系统(对齐 AGENTS.md 自身的防护水平 — 见 §5)。

## 4. claude R15 修正的落点

1. **影子模式(1-2 周)**: `mode=draft` 只起草 + 日志不写入; 量噪声率(批准率 <30% → 重校句式与起草 prompt)。
2. **复发联动 = keep/kill 信号**: 每行计数(见 §2 淘汰); 4 周试点预登记 kill 规则(§5)。
3. **可见性**: 每次写入/跳过一行日志(原因: 候选满/起草失败/段落满/去重合并/marker 异常), 可查。
4. **安全 = 对齐 AGENTS.md 防护水平**: 同 UID 的 agent 本就能直接改 AGENTS.md(更强的注入通道), 本设计不额外建密码学防线; 保留: 总开关、fail-closed、段外零写、机器不改已批准行。**若未来要求真隔离(独立 UID/权限), 那是宿主级课题, 不在本设计内。**

## 5. 验证与停止(预登记, 不得事后放宽)

- 影子期(1-2 周): 看起草质量与批准率。
- 试点(4 周, 最忙项目): 任一为真即停 —
  a. 已写行的同主题复发 ≥ 历史一半(规则在文件里却没管用);
  b. 多数复发发生时对应行已在文件中;
  c. 你手动删掉一半以上的行;
  d. 你发现自己宁愿直接手改指令文件(主观, 最强信号)。
- 不建 RCT/标签器/挑战集(R15 反转裁决); 统计 = 每行计数 + 文件大小, 一眼可读。
- 到期证据不足 ≠ 证明无效; 但 kill 规则触发即停, 不解释。

## 6. 配置

```jsonc
// opencode.json → plugin.supervisor
"memoryMode": "off" | "draft" | "write"   // 默认 off
```

数据(候选/日志/计数)在 `~/.local/share/opencode/storage/plugin/supervisor/memory/` — **非权威**; 权威 = AGENTS.md 本身。
